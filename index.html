🌟 ภาพรวม: Microsoft SLA คืออะไร

Service Level Agreement (SLA) คือสัญญาที่ Microsoft ให้ไว้กับลูกค้าเกี่ยวกับ uptime และ connectivity ของ Online Services ต่าง ๆ เช่น Azure, Microsoft 365, Dynamics 365 และ Intune

SLA ครอบคลุมบริการ: Azure  |  Microsoft 365  |  Dynamics 365  |  Enterprise Mobility Suite

สูตรคำนวณ Monthly Uptime Percentage

# สูตรมาตรฐาน Microsoft
Monthly Uptime % = (Total Billable Minutes − Downtime Minutes) ÷ Total Billable Minutes × 100

# ตัวอย่าง: เดือนมี 43,200 นาที, เกิด Downtime 120 นาที
= (43200 − 120) ÷ 43200 × 100 = 99.72%
⚠️
ข้อควรทราบ: SLA วัดตาม definition ของ Microsoft ไม่ใช่ตาม perception ของลูกค้า เวลา Maintenance ที่นัดไว้ล่วงหน้า, เหตุสุดวิสัย (force majeure), หรือ configuration ของลูกค้าเองที่ไม่ถูกต้อง จะ ไม่นับเป็น Downtime ตาม SLA

ตาราง Credit ที่ได้รับ (ตัวอย่าง Standard Tier)

Monthly Uptime PercentageService Credit ที่ได้รับ
≥ 99.9%ไม่ได้ Credit — เป็นไปตาม SLA
< 99.9%10% ของค่าบริการรายเดือน
< 99%25% ของค่าบริการรายเดือน

* อัตรา Credit จริงขึ้นอยู่กับ service tier — ดูเอกสาร SLA ฉบับล่าสุดจาก microsoft.com/licensing

🔎 ขั้นตอนที่ 1 — ตรวจจับ Outage

เปิด Service Health Dashboard ไปที่ Microsoft 365 Admin Center → Health → Service Health หรือ Azure Portal → Help + support → Service Health
จดบันทึก Incident ID รหัส Incident จะอยู่ในรูปแบบ EX25194 (ตัวอักษร 2 ตัว + ตัวเลข) ดูตารางรหัสบริการด้านล่าง
อ่าน Post Incident Review (PIR) หลัง Incident ปิด Microsoft จะออก PIR ซึ่งระบุ root cause, timeline และผลกระทบอย่างเป็นทางการ
ℹ️
Advisory Incidents ≠ SLA Credit: Incident ที่ระบุว่า "Advisory" (อาจได้รับผลกระทบ) โดยปกติ ไม่มีสิทธิ์ขอ SLA Credit ต้องเป็น Incident ที่ระบุว่า tenant ของคุณ ได้รับผลกระทบจริง

📊 ขั้นตอนที่ 2 — ประเมิน SLA (5-Pass Method)

🔐 Pass 1: Definitions

อ่านนิยามของ Downtime, Valid Request, Total Billable Minutes ในเอกสาร SLA ก่อนเสมอ — นิยามเหล่านี้กำหนดว่าอะไรนับเป็น failure จริง

📈 Pass 2: Measurement

ทำความเข้าใจวิธีคำนวณ — time-based vs. request-based, retry requirement, และ aggregation scope (per instance หรือ across subscription)

❌ Pass 3: Exclusions

ระบุเงื่อนไขที่ ไม่ครอบคลุม: planned maintenance, force majeure, customer misconfiguration, exceeded quota, preview features

💡 Pass 4: Design Signals

ใช้ SLA เป็น input สำหรับ architecture — เช่น ถ้า SLA ต้องการ retry logic ให้ implement ก่อน ไม่เช่นนั้น failure จะไม่นับใน SLA

📋 Pass 5: ตรวจสอบว่า Incident ละเมิด SLA หรือไม่

คำนวณ Monthly Uptime % จากข้อมูลจริง ใช้สูตร: (Total Billable Min − Downtime Min) ÷ Total Billable Min × 100
หักเวลาที่ไม่นับ ลบ planned maintenance, excluded events, และช่วงที่ configuration ไม่ตรงตาม prerequisite
เปรียบเทียบกับ SLA Threshold ถ้าตัวเลขต่ำกว่า committed % (เช่น 99.9%) คุณมีสิทธิ์ยื่นขอ Credit

📄 ขั้นตอนที่ 3 — รวบรวมหลักฐาน

หลักฐานที่ต้องเตรียมก่อนยื่นเคลม

  • Customer Tenant GUID — ID ของ tenant ที่ได้รับผลกระทบ
  • Outage Incident Identifier — เช่น EX25194 จาก Service Health Dashboard
  • Timestamps — เวลาเริ่มและสิ้นสุด Incident พร้อม timezone
  • Error Details — Error codes, error messages, timeout behaviors ที่พบ
  • Request Logs — Log ที่แสดง retry attempts (ถ้า SLA กำหนดให้ retry)
  • จำนวนและที่ตั้งของ Users ที่ได้รับผลกระทบ
  • Email จากลูกค้า — ต้องส่งจาก domain ของ tenant ที่ได้รับผลกระทบ (ไม่รับ personal email)
  • Support Ticket Number — เลข ticket ที่เปิดไว้กับ Microsoft
  • ซื้อผ่าน CSP? — ระบุว่า subscription ซื้อผ่าน Cloud Solution Provider หรือไม่
❌
ไม่เพียงพอ: ชื่อลูกค้า, Tenant ID, Partner Ticket Number และ Ticket Timestamp ไม่เพียงพอสำหรับ process credit — ต้องมีหลักฐานจากรายการด้านบนครบถ้วน

🆕 ขั้นตอนที่ 4 — วิธีการเคลม SLA Credit

☁️ Microsoft Azure

Sign in ที่ Azure Portal ด้วย account ที่ได้รับผลกระทบ
ไปที่ Help + Support → New Support Request
เลือก Issue type: Billing → Problem type: Refund Request
ระบุว่าขอ SLA credit พร้อม วันที่/เวลา/timezone และ impacted services
ตรวจสอบ contact details → Create

💼 Microsoft 365 / Office 365 / Dynamics CRM

ไปที่ Partner Center (สำหรับ CSP Partner)
เลือก Customer → Service Request → New Request
เลือก workload ที่ได้รับผลกระทบ — portal จะ redirect ไปยัง workload portal
กรอกข้อมูล — ใส่ contact ของ Partner ไม่ใช่ contact ลูกค้า
Submit → ติดตาม ticket ใน M365 Admin Center → Support Tickets

📌 CSP Partner: ขอ Credit ผ่าน Partner Center

ℹ️
Credit requests รับเฉพาะจาก CSP Direct และ Indirect Providers เท่านั้น — Indirect Resellers ไม่สามารถยื่นได้โดยตรง
สร้าง Support Ticket ใน Partner Center → เลือก topic: SLA Credit / Service Outage
แนบหลักฐานทั้งหมดตามรายการใน Section รวบรวมหลักฐาน
รอการอนุมัติ — Credit จะปรากฏใน invoice และ reconciliation data รอบถัดไป
✅
Credit จะครอบคลุมเฉพาะ service ที่ได้รับผลกระทบจริง: เช่น ถ้า M365 Suite เจอปัญหาแค่ SharePoint — credit จะได้เฉพาะ SharePoint ไม่ใช่ทั้ง suite และ credit ไม่ครอบคลุม lost revenue หรือ reputational damage
